Use Case Diagram dan Use Case Description
1. Tujuan Praktikum
    1. Mengidentifikasi batas sistem, aktor, kebutuhan, aturan bisnis, dan asumsi berdasarkan skenario.
    2. Menentukan use case berdasarkan tujuan aktor dalam menggunakan sistem.
    3. Membuat use case diagram sesuai kebutuhan dan hubungan antara aktor dengan sistem.
    4. Menyusun use case description yang mencakup pemicu, prasyarat, alur utama, alur alternatif, dan pascakondisi.
    5. Memahami keterkaitan antara kebutuhan sistem dengan use case yang dibuat.
    6. Memperbaiki diagram berdasarkan hasil evaluasi.
2. Dasar Teori
Use Case Diagram merupakan salah satu diagram UML yang digunakan untuk menggambarkan fungsi-fungsi yang tersedia dalam suatu sistem serta interaksi antara aktor dengan sistem tersebut.

Aktor adalah pihak yang berinteraksi dengan sistem, baik berupa manusia maupun sistem lain. Use case merupakan fungsi atau layanan yang disediakan oleh sistem untuk memenuhi kebutuhan aktor.

Selain use case diagram, terdapat use case description yang berfungsi menjelaskan suatu use case secara lebih terperinci. Use case description terdiri dari beberapa bagian, yaitu pemicu (trigger), prasyarat (precondition), alur utama (main flow), alur alternatif (alternative flow), dan pascakondisi (postcondition).

Terdapat juga beberapa hubungan dalam use case diagram, seperti association untuk menghubungkan aktor dengan use case, include untuk menunjukkan fungsi yang selalu digunakan, dan extend untuk menunjukkan fungsi tambahan berdasarkan kondisi tertentu.
3. Hasil Praktikum
Pada praktikum ini dilakukan analisis terhadap studi kasus Sistem Informasi Peminjaman dan Pengembalian Peralatan Laboratorium Kampus.

Kegiatan dimulai dengan mengidentifikasi aktor, kebutuhan sistem, aturan bisnis, dan batas sistem. Selanjutnya, dibuat use case diagram yang menggambarkan hubungan antara aktor dengan fungsi-fungsi yang tersedia.

Setelah diagram selesai dibuat, dilakukan penyusunan dua use case description yang berisi pemicu, prasyarat, alur utama, alur alternatif, dan pascakondisi. Hasil pemodelan kemudian diperiksa untuk memastikan kesesuaiannya dengan kebutuhan sistem.
4. Analisis
Berdasarkan praktikum yang dilakukan, use case diagram dapat membantu menggambarkan kebutuhan fungsional sistem secara lebih sederhana dan terstruktur. Dengan adanya aktor dan use case, hubungan antara pengguna dengan layanan sistem dapat diketahui dengan jelas.

Use case description melengkapi diagram karena memberikan penjelasan mengenai proses interaksi secara lebih terperinci. Kesesuaian antara diagram dan deskripsi sangat penting agar tidak terjadi perbedaan pemahaman mengenai fungsi sistem.
5. Kesimpulan
Praktikum ini memberikan pemahaman mengenai pembuatan use case diagram dan use case description. Mahasiswa dapat mengidentifikasi aktor, menentukan fungsi sistem, serta menjelaskan proses interaksi antara pengguna dan sistem secara terstruktur berdasarkan kebutuhan yang telah dianalisis.
